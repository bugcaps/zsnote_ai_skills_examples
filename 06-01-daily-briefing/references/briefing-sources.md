# 출처 판정과 상태 표기

## 상태 기호 네 가지

| 기호 | 뜻 | 이 기호를 쓰는 때 |
| :--- | :--- | :--- |
| `읽음` | 출처를 실제로 읽었고 항목이 1건 이상 있다 | 도구 호출이나 파일 읽기가 성공했다 |
| `0건` | 출처를 실제로 읽었고 항목이 0건이다 | **"일정이 없습니다"라고 말해도 되는 유일한 경우** |
| `확인 못 함` | 출처를 읽지 못했다 | 도구가 없거나, 권한이 거부됐거나, 파일을 못 읽었거나, 사용자가 자료를 주지 않았다 |
| `해당 없음` | 이 브리핑에서 그 출처를 쓰지 않기로 했다 | 사용자가 제외했거나 애초에 대상이 아니다 |

`0건`과 `확인 못 함`을 섞어 쓰면 이 스킬은 실패한 것입니다. 둘 사이에서 망설여지면 `확인 못 함`입니다.

## 판정 순서

출처마다 아래 순서를 밟고, 어느 단계에서 멈췄는지를 수집 결과 표에 남깁니다.

1. **능력으로 판정합니다.** "그 일을 할 수 있는 도구가 지금 호출 가능한가"만 봅니다. 특정 서비스·커넥터·API 이름을 찾지 않고, 없는 도구 이름을 지어내지도 않습니다.
2. 호출 가능하면 호출하고, 결과 건수에 따라 `읽음` 또는 `0건`으로 적습니다.
3. 호출할 수 없으면 아래 표의 대체 경로를 사용자에게 안내하고 시도합니다.
4. 대체 경로까지 막히면 `확인 못 함`으로 적고 **브리핑은 계속합니다.** 한 출처가 막혔다고 나머지를 버리지 않습니다.

## 출처별 대체 경로

| 출처 | 순서 | 다 막혔을 때 |
| :--- | :--- | :--- |
| 기준 시각 | (1) `scripts/collect_agenda.py` 실행 → (2) 사용자에게 오늘 날짜 질문 | 없음. 기준 시각 없이 브리핑하지 않습니다. 사용자에게 받았으면 출처를 `사용자 제공`으로 적습니다 |
| 일정 | (1) 캘린더 읽기 도구 → (2) 사용자가 내보낸 `.ics` 파일을 스크립트로 파싱 → (3) 사용자가 붙여 넣은 일정 텍스트 | `확인 못 함` |
| 할 일 | (1) 사용자가 지정한 로컬 파일 → (2) 사용자가 붙여 넣은 목록 | `확인 못 함`. 우선순위 제안에서 할 일 근거를 빼고 그 사실을 적습니다 |
| 메일 | (1) 메일 읽기 도구 | `확인 못 함`. 도구가 있어도 **건수와 제목까지만** 보고합니다 |
| 날씨 | (1) 날씨 조회 도구 | `확인 못 함`. 행을 지우지 않습니다. 기억이나 추측으로 날씨를 적지 않습니다 |

`해당 없음`은 **사용자가 그 출처를 빼라고 말했을 때만** 씁니다. 도구가 없어서 못 읽은 것은 언제나 `확인 못 함`입니다. 날씨처럼 조회 도구가 흔히 없는 출처도 행을 지우지 않습니다. 행이 사라지면 읽어 본 것인지 아닌지를 독자가 알 수 없어, 이 스킬이 막으려는 "조용히 비우기"가 됩니다.

## 수집 결과 표 양식

브리핑 맨 앞에 이 표를 놓습니다.

한 행에는 상태를 하나만 적습니다. 상태가 갈리면 행을 나눕니다. 스크립트가 펼치지 못한 반복 일정은 `일정` 행에 섞지 말고 **`일정(반복)` 행을 따로 만들어** `확인 못 함`으로 적습니다.

| 출처 | 상태 | 건수 | 기준 시각 |
| :--- | :--- | :--- | :--- |
| 일정 | 읽음 | 3 | 2026-09-21 08:10 |
| 일정(반복) | 확인 못 함 | 1 | 2026-09-21 08:10 |
| 할 일 | 확인 못 함 | - | - |
| 메일 | 0건 | 0 | 2026-09-21 08:11 |
| 날씨 | 확인 못 함 | - | - |

`일정(반복)` 행의 건수는 **펼치지 못한 반복 일정의 개수**이지 대상 날짜의 일정 수가 아닙니다. 반복 일정이 하나도 없으면 이 행을 만들지 않습니다.

## scripts/collect_agenda.py

터미널에 아래 한 줄을 그대로 붙여 넣으면 됩니다. 읽기만 하며 일정을 바꾸지 않습니다.

```
python scripts/collect_agenda.py
python scripts/collect_agenda.py --ics data/sample-calendar.ics --date 2026-09-21
python scripts/collect_agenda.py --ics <내보낸 파일 경로> --date tomorrow
```

- `--date` 는 `today` · `tomorrow` · `YYYY-MM-DD` 를 받습니다. 기본값은 `today` 입니다.
- 첫 줄은 언제나 기준 시각입니다. `--ics` 를 주지 않아도 이 줄은 나옵니다.
- 종료 코드 `0` = 기준 시각 출력 성공, `1` = `.ics` 파일을 읽지 못했거나 캘린더 파일이 아님, `2` = 입력 오류.
- 종료 코드 `1`은 브리핑 중단 신호가 아니라 **일정 칸을 `확인 못 함`으로 적으라는 신호**입니다.
- **스크립트가 `0건`을 출력하는 경우는 하나뿐입니다.** 파일에 `BEGIN:VCALENDAR`가 있고 대상 날짜의 일정이 실제로 0개일 때입니다. 캘린더가 아닌 파일이나 0바이트 파일은 `0건`이 아니라 `확인 못 함`(종료 코드 `1`)으로 나옵니다. 스크립트가 `0건`이라고 말하지 않았는데 브리핑에 "일정이 없습니다"라고 쓰지 않습니다.

**반복 일정(`RRULE`)은 펼치지 않습니다.** 스크립트가 반복 일정을 `[확인 못 함]` 블록에 따로 출력하므로, 그 목록은 `일정` 행의 건수에 더하지 말고 위의 `일정(반복)` 행으로 옮겨 적습니다. 정확한 반복 일정이 필요하면 캘린더 읽기 도구를 쓰거나 사용자에게 직접 확인합니다.

`data/sample-calendar.ics` 는 동작을 확인하려고 만든 **가상 샘플**입니다. 실제 일정으로 쓰지 않습니다.
