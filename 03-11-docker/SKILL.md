# 도커 이미지 빌드 및 최적화

동작하는 Dockerfile이 아니라 운영에 올릴 수 있는 Dockerfile을 만듭니다.

## 작업 순서

1. **프로젝트 파악**: 언어·런타임 버전·빌드 단계 유무·시작 명령을 패키지 매니저 파일에서 확인합니다. 네이티브 모듈(`node-gyp`, C 확장) 의존성이 있는지도 봅니다.
2. **기준 확인**: `references/docker-best-practices.md`를 읽고 베이스 이미지와 스테이지 구성을 결정합니다.
3. **작성**: `Dockerfile`과 `.dockerignore`를 함께 작성합니다. 기존 파일이 있으면 덮어쓰지 않고 변경점을 먼저 보여줍니다.
4. **검증**: Docker를 쓸 수 있으면 `docker build`로 빌드가 되는지 확인합니다. 쓸 수 없으면 빌드하지 못했음을 보고에 적습니다.
5. 체크리스트로 점검한 뒤, 선택한 베이스 이미지와 그 이유를 함께 보고합니다.

## 핵심 규약

- 베이스 이미지는 **런타임 버전을 고정한 경량 태그**(`node:22-slim`, `python:3.12-slim` 등)를 씁니다. `latest`와 버전 없는 태그를 쓰지 않습니다.
- Alpine은 네이티브 모듈이 없을 때만 선택합니다. 있으면 `-slim`을 씁니다.
- 의존성 설치 레이어를 소스 복사 레이어보다 먼저 둡니다.
- 빌드 단계가 있거나 개발 의존성이 있으면 멀티 스테이지로 나누고, 최종 이미지에는 운영 의존성과 빌드 결과물만 복사합니다.
- 최종 스테이지는 루트가 아닌 사용자로 실행합니다.
- 시크릿(`.env`, 토큰)을 `COPY`하거나 `ARG`/`ENV`로 굽지 않습니다.

## 체크리스트

- [ ] 베이스 이미지 태그에 버전이 고정되어 있다
- [ ] 의존성 설치가 소스 복사보다 위에 있다
- [ ] 최종 이미지에 개발 의존성과 빌드 도구가 없다
- [ ] `USER`로 비-루트 사용자를 지정했다
- [ ] `.dockerignore`에 `node_modules`, `.git`, `.env`가 있다
- [ ] 빌드 여부(성공 / 실행 불가)를 보고했다
