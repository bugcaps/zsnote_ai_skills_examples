# UI 접근성(a11y) 및 UX 점검

체크리스트 항목마다 판정 주체가 다릅니다. **계산은 스크립트가, 구조 점검은 에이전트가, 실제 사용 확인은 사람이** 합니다.

## 작업 순서

1. **색상 값 추출**: 대상에서 전경/배경 색 쌍을 모두 뽑아 `전경 배경 설명` 형식으로 파일에 적습니다. 코드가 아니라 이미지 시안이면 색을 추출할 수 없으므로, 사용자에게 HEX 값을 요청하거나 "명암비 미검증"으로 표시합니다.
2. **명암비 계산**: `python scripts/contrast.py --pairs <파일>`을 실행합니다. 큰 텍스트(18pt 이상 또는 14pt 굵은 글씨)와 아이콘·테두리 같은 그래픽 요소는 `--large`(3:1 기준)로 따로 실행합니다.
3. **구조 점검**: `references/a11y-checklist.md`의 나머지 항목(키보드, 레이블, 헤딩, 대체 텍스트)을 코드와 대조합니다.
4. **리포트 작성**: 아래 형식으로 보고합니다.

```text
## 1. 자동 판정 (스크립트)   스크립트 출력을 그대로 인용
## 2. 구조 점검 (에이전트)   위반 항목 + 수정 코드
## 3. 사람이 확인할 것       스크립트도 코드도 판정할 수 없는 항목
```

## 핵심 규약

- **명암비를 직접 계산하지 않습니다.** 리포트의 모든 명암비 수치는 스크립트 출력에서 인용한 값이어야 합니다.
- 지적마다 달성 기준(4.5:1, 3:1 등)과 수정 코드를 함께 제시합니다. "신경 쓰세요" 같은 조언만으로 끝내지 않습니다.
- **`alt` 텍스트의 적절성, 포커스 순서의 자연스러움, 오류 안내의 이해도는 판정하지 않고 3절로 넘깁니다.** 코드만 보고 알 수 없는 항목입니다.
- 이미지 시안만 받은 경우 색을 눈으로 추정해 수치를 말하지 않습니다.

## 체크리스트

- [ ] `contrast.py`를 실행했고 출력을 1절에 인용했다
- [ ] 큰 텍스트·그래픽 요소는 `--large`로 따로 판정했다
- [ ] 구조 점검 항목마다 수정 코드가 있다
- [ ] 코드로 판정할 수 없는 항목을 3절에 분리했다
