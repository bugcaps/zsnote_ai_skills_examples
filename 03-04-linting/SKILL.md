# 코드 리뷰 및 정적 분석

기계가 판정할 수 있는 문제는 스크립트가 찾고, 에이전트는 스크립트가 볼 수 없는 설계 문제만 리뷰합니다.

## 작업 순서

1. **정적 분석 실행**: 코드를 읽기 전에 `node scripts/run-linter.js <대상 파일>`을 먼저 실행합니다.
2. **결과 해석**: 출력은 `LEVEL 파일:줄 [규칙] 메시지` 형식이고, 종료 코드 1은 ERROR가 있다는 뜻입니다. 마지막 `요약:` 줄로 건수를 확인합니다.
3. **심층 리뷰**: 이제 코드를 읽고, 스크립트가 잡지 못하는 논리 오류·가독성·구조 문제를 리뷰합니다. ERROR가 있으면 그 줄의 원인부터 살핍니다.
4. **리포트 작성**: 아래 형식으로 보고합니다.

```text
## 1. 정적 분석 결과   (스크립트 출력을 그대로 인용)
## 2. 설계 리뷰        (에이전트의 판단. 근거가 된 줄 번호 포함)
## 3. 수정 제안        (우선순위 순)
```

## 핵심 규약

- **스크립트가 보고하지 않은 문법·컨벤션 문제를 직접 지어내지 않습니다.** 1절에는 스크립트 출력에 있는 항목만 씁니다.
- 스크립트를 실행할 수 없으면(Node 없음, 파일 없음) 리뷰를 진행하지 않고 그 사실을 먼저 알립니다.
- ERROR가 있으면 설계 제안보다 ERROR 수정 방안을 먼저 제시합니다.
- 코드를 직접 고치지 않습니다. 수정은 사용자가 요청할 때만 합니다.

## 체크리스트

- [ ] 코드를 읽기 전에 `run-linter.js`를 실행했다
- [ ] 1절의 모든 항목이 스크립트 출력에 실제로 존재한다
- [ ] 기계적 지적(1절)과 설계 지적(2절)이 섞이지 않았다
- [ ] 2절의 지적마다 줄 번호가 있다
