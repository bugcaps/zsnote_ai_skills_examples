# 단위 테스트 자동 생성

정상 경로 하나만 확인하는 테스트가 아니라, 경계값과 실패 상황을 검증하는 테스트를 프로젝트 스타일로 작성합니다.

## 작업 순서

1. 대상 함수의 시그니처와 분기(if, 예외, 외부 호출)를 읽고 **테스트할 상황 목록**을 먼저 만듭니다: 정상 경로, 경계값, 실패 상황.
2. `assets/test_template.py`를 읽고 그 구조(import 순서, 픽스처, Arrange-Act-Assert 주석, 함수명 형식)를 그대로 따릅니다.
3. 프로젝트의 `tests/`에 기존 테스트가 있으면 1개를 읽고, 템플릿과 다르면 **기존 테스트가 우선**입니다.
4. 테스트를 작성한 뒤 `pytest <작성한 파일> -q`를 실행합니다. 실패하면 **테스트가 틀렸는지 대상 코드가 틀렸는지** 구분해 보고하고, 대상 코드는 고치지 않습니다.
5. 아래 체크리스트로 점검한 뒤 상황 목록과 실행 결과를 함께 보고합니다.

## 핵심 규약

- 테스트 함수명은 `test_<대상함수>_<상황>_<기대결과>` 형식입니다.
- 같은 검증을 입력만 바꿔 반복할 때는 `pytest.mark.parametrize`로 묶습니다.
- 외부 호출(네트워크, DB, 시간)은 `pytest-mock`의 `mocker`로 대체합니다. 대상 함수 자체를 mock하지 않습니다.
- 통과시키려고 assert를 느슨하게 바꾸지 않습니다(`assert result` 같은 검증 금지).

## 체크리스트

- [ ] 경계값(None, 빈 값, 0, 음수 등) 테스트가 1개 이상 있다
- [ ] 예외 상황을 `pytest.raises`로 검증한다
- [ ] 반복되는 검증은 `parametrize`로 묶었다
- [ ] pytest를 실제로 실행했고 결과를 보고에 포함했다
