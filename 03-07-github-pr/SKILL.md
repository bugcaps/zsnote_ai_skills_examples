# PR 초안 작성

diff에서 알 수 있는 것만 채우고, 알 수 없는 것은 빈칸으로 남겨 사람에게 넘깁니다.

## 작업 순서

1. **변경 사항 파악**: 사용자가 diff를 주지 않았다면 `git diff main...HEAD --stat`과 `git log main..HEAD --oneline`으로 확인합니다. 기준 브랜치가 `main`이 아니면 사용자에게 묻습니다.
2. **템플릿 읽기**: 저장소에 `.github/PULL_REQUEST_TEMPLATE.md`가 있으면 그것을, 없으면 `assets/PR_TEMPLATE.md`를 읽습니다.
3. **내용 작성**: 템플릿의 섹션 제목과 순서를 그대로 두고 내용만 채웁니다.
4. **출력**: 체크리스트로 점검한 뒤 PR 본문만 마크다운으로 출력합니다.

## 핵심 규약

- 인사말, 머리말, 맺음말 없이 PR 본문만 출력합니다.
- Changes는 `파일 또는 모듈: 무엇을 바꿨는지` 형태의 개조식으로 씁니다.
- **diff에서 확인할 수 없는 항목은 `[TODO: 작성 필요]`로 남깁니다.** 테스트 방법, 작업 배경이 여기에 해당합니다.
- **이슈 번호는 추측하지 않습니다.** 브랜치명이나 커밋 메시지에 `#123` 형태로 명시된 경우에만 적습니다.
- PR을 직접 생성(`gh pr create`)하지 않습니다. 초안 출력까지만 합니다.

## 체크리스트

- [ ] 템플릿의 모든 섹션이 같은 순서로 들어 있다
- [ ] Changes의 모든 항목을 diff에서 찾을 수 있다
- [ ] 확인할 수 없는 항목은 `[TODO: 작성 필요]`로 남겼다
- [ ] 본문 앞뒤에 다른 말이 없다
