# 첨삭 판정 규약

## 지적의 세 갈래

| 갈래 | 뜻 | 제안 칸에 넣는 것 |
| :--- | :--- | :--- |
| `고쳐 쓸 수 있음` | 원문에 있는 사실만으로 표현을 다듬을 수 있다 | 고친 문장 **한 개** |
| `확인 필요` | 원문에 없는 사실을 알아야 고칠 수 있다 | 고친 문장 대신 `[확인 필요: ...]`와 물어볼 것 한 줄 |
| `지적하지 않음` | 아래 「지적하지 않는 것」에 걸린다 | 목록에 올리지 않는다 |

## 판정 순서

고칠 자리마다 아래 순서를 그대로 밟습니다. **순서를 바꾸면 사람이 정할 일을 에이전트가 먼저 정해 버립니다.**

1. **「지적하지 않는 것」 표에 걸리는가?** 걸리면 다른 조건을 보지 않고 목록에서 뺍니다. **표가 언제나 이깁니다.**
2. **고치려면 원문에 없는 사실이 필요한가?** 수치·기간·직책·규모·성과가 있어야 문장이 완성되면 `확인 필요`입니다.
3. **둘 다 아니면** `고쳐 쓸 수 있음`입니다.
4. **망설여지면 `확인 필요`입니다.** 지어내는 것보다 묻는 쪽이 언제나 덜 위험합니다.

## 지적하는 것

아래 표에 있는 항목만 지적합니다. 표에 없는 것은 눈에 거슬려도 지적하지 않습니다.

| 항목 | 걸리는 기준(눈으로 셀 수 있게) | 고치는 방향 |
| :--- | :--- | :--- |
| 긴 문장 | 한 문장이 공백 포함 80자를 넘거나, 한 문장에 서술어가 3개 이상 | 문장을 나눕니다. **낱말을 더하거나 빼지 않습니다.** 나누느라 이어 주는 말(`~하고`·`~한 뒤`)을 끝맺음으로 바꾸는 것까지만 허용하고, 지원자가 적은 주장·경험은 한 조각도 지우지 않습니다 |
| 상투구 | 아래 「상투구 목록」에 있는 표현 | 그 자리에서 실제로 한 일로 바꿉니다. 한 일이 원문에 없으면 `확인 필요` |
| 수치 없는 성과 | `크게`·`많이`·`대폭`·`상당히`·`획기적으로` 같은 정도 부사가 성과 서술에 붙음 | 고치지 않고 `확인 필요`. 숫자를 채워 넣지 않습니다 |
| 역할이 안 보이는 문장 | `~에 참여했습니다`·`~에 기여했습니다`처럼 본인이 무엇을 했는지 없음 | 고치지 않고 `확인 필요`. 임의로 `주도`·`총괄`로 올리지 않습니다 |
| 같은 말 반복 | 같은 낱말이나 표현이 한 문서에 3번 이상 | 한 곳만 남기고 나머지는 다른 말로 바꾸거나 뺍니다 |
| 수동태·명사 나열 | `~이 이루어졌습니다`·`~되었습니다`, 또는 `A의 B의 C` 3단 이상 | 주어를 세운 능동형 한 문장으로 |
| 맞춤법·띄어쓰기 | 명백한 오기 | 바로 고칩니다 |
| 어투 섞임 | 한 문서 안에 `~습니다`와 `~했다`가 섞여 있음 | 섞여 있다는 사실만 **한 번** 적고 더 많이 쓰인 쪽으로 맞추자고 제안합니다. 어느 어투가 나은지는 정하지 않습니다 |
| 지원 직무와 겉도는 문단 | 문서에 `지원 직무`가 적혀 있으면 그것을 근거로 본다. **회사에 맞춘 지적은 사용자가 회사를 말한 경우에만** 한다 | 빼거나 줄이는 것을 제안만 하고, 대신 쓸 내용을 지어내지 않습니다 |

**서술어를 셀 때는** `~하고`·`~하여`·`~며`처럼 문장을 이어 주는 것과 문장을 끝맺는 것만 셉니다. `~한`·`~는`·`~던`처럼 뒷말을 꾸미는 것과 `~기`·`~것` 같은 명사형은 세지 않습니다. 이 셈법은 위 표의 `서술어 3개 이상`과 아래 「지적 개수와 우선순위」의 `서술어 5개 이상`에 함께 씁니다.

## 상투구 목록

## 지적하지 않는 것

| 항목 | 예 | 지적하면 생기는 일 |
| :--- | :--- | :--- |
| 경력 선택 | 이직 횟수, 공백기, 업종 전환, 계약직 이력 | 사람이 살아온 결정을 문서의 결함으로 다루게 됩니다 |
| 진로 판단 | "이 직무는 안 맞아 보입니다", 다른 회사 권유 | 묻지 않은 조언이 첨삭을 덮습니다 |
| 합격 가능성 | 점수, 등급, 합격 확률, "이 정도면 되겠네요" | 알 수 없는 것을 아는 척하게 됩니다 |
| 채용 담당자의 취향 추정 | "인사담당자는 이런 문장을 싫어합니다" | 근거 없는 규칙이 사실처럼 남습니다 |
| 학력·나이·성별·출신지 | 전공, 졸업 연도, 나이 | 고칠 수 없는 것을 지적하게 됩니다 |
| 사용자가 고른 어투 | `~습니다`를 `~했다`로 통일하라는 식의 취향 | 사용자가 고른 목소리를 빼앗습니다. 다만 **한 문서 안에서 어투가 섞여 있으면** 그 사실만 한 번 적습니다 |

이 표는 "그 대목이 괜찮다"는 뜻이 아니라 **"에이전트가 판단할 자리가 아니다"**는 뜻입니다.

## 지적 개수와 우선순위

- 한 번에 내보내는 지적은 **최대 12개**입니다. 넘으면 아래 우선순위로 12개만 적고, 나머지는 `다루지 않은 지적 N건`으로 **건수만** 적습니다. 무엇이었는지 힌트도 적지 않습니다.
- **한 문단에서 최대 2개**까지만 지적합니다. 한 문단이 통째로 지적으로 덮이면 사용자는 그 문단을 다시 쓰게 되고, 그러면 전문 재작성과 같아집니다.
- 글머리 목록(경력 기술처럼 항목이 줄줄이 나오는 부분)은 **항목 하나를 한 문단으로 세되, 한 항목에는 지적 1개**까지만 답니다.
- 문장 하나만 받은 경우에는 **최대 3개**까지만 지적합니다.
- 우선순위는 위에서부터입니다.
  1. `확인 필요` — 사실이 비어 있어 사람만 채울 수 있는 자리
  2. 읽는 사람이 뜻을 잘못 읽을 문장
  3. 상투구와 같은 말 반복
  4. 길이·수동태·맞춤법
- **공백 포함 110자를 넘거나 서술어가 5개 이상인 문장은 길이를 2순위로 봅니다.** 이만큼 길어지면 읽는 사람이 주어와 서술어를 짝지어 읽지 못해 뜻이 잘못 읽히기 때문입니다. 110자 이하이면서 서술어가 4개 이하이면 길이는 4순위 그대로입니다.
- **한 문장에 두 갈래 이상이 겹치면 우선순위가 높은 것 하나로만** 적습니다. 같은 문장을 두 번 지적하지 않습니다. 위 승격에 걸린 긴 문장은 상투구·반복보다 먼저이므로 `고쳐 쓸 수 있음`으로 나누어 제안합니다.

## 지적 양식

지적마다 아래 세 칸을 답니다. 칸 이름을 바꾸거나 빼지 않습니다.

```
### 지적 3 — 확인 필요 · 2문단 1번째 문장
원문: "담당 제품의 매출을 크게 늘렸습니다."
제안: [확인 필요: 매출이 얼마에서 얼마로 늘었는지, 어느 기간인지]
이유: `크게`는 읽는 사람마다 다르게 읽힙니다. 숫자는 지원자만 알고 있으므로 여기서 채우지 않습니다.
물어볼 것: 그 기간 매출이 얼마에서 얼마로 바뀌었습니까? 답을 받은 뒤에도 문장은 직접 쓰십시오.
```

- **원문은 그대로 옮깁니다.** 줄이거나 `...`로 자르지 않습니다. 사용자가 원문과 제안을 나란히 놓고 골라야 합니다.
- **제안은 한 개만 답니다.** 판본을 여러 개 늘어놓으면 고르는 부담이 다시 사람에게 넘어갑니다.
- **이유는 한두 줄입니다.** 문서 안에서 확인되는 근거만 적고, 채용 관행이나 합격 가능성을 근거로 들지 않습니다.
- `고쳐 쓸 수 있음`이면 `제안` 칸에 고친 문장을 넣고 `물어볼 것` 줄은 뺍니다.

## 요약 줄

목록 끝에 한 줄로 적습니다.

`검토한 문장 {{ N }}개 · 지적 {{ M }}건 = 고쳐 쓸 수 있음 {{ }} + 확인 필요 {{ }} · 다루지 않은 지적 {{ }}건`

- 두 갈래의 합이 지적 건수와 같아야 합니다.
- 상한에 걸려 뺀 것이 없으면 마지막 항목은 `0건`으로 적고 칸을 지우지 않습니다.
- `지적하지 않음`으로 판정한 것은 이 줄에 세지 않습니다. 세는 순간 "지적했지만 참았다"는 말이 되어 사용자에게 다시 판단을 흘립니다.

## 연습용 샘플

`data/sample-resume.md`에서 **첫 `---` 아래부터가 검토 대상 서류**이고 그 위 머리말은 첨삭 대상이 아닙니다. 세 갈래가 모두 나오도록 지어낸 **가상 지원 서류**입니다. 인물·회사·학교·연락처 모두 실존하지 않으며, 메일 주소는 `example.invalid` 도메인입니다. 실제 지원에 쓰지 않고 파일을 고치지도 않습니다.
