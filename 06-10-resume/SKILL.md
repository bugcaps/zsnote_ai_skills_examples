# 이력서·자기소개서 첨삭

**다시 써 준 이력서는 더 이상 사용자의 이력서가 아닙니다.** 매끄럽게 고친 전문을 건네면 사용자는 그대로 제출하고, 면접에서 자기가 쓰지 않은 문장에 대해 질문을 받습니다. 그래서 이 스킬은 전문을 만들지 않고 **원문·제안·이유 세 칸의 지적 목록**만 내보내, 무엇을 받아들일지는 사람이 고르게 합니다.

## 작업 순서

1. **무엇을 받았는지 확인합니다.** 문서 전체인지 문장 한두 줄인지 정하고, 이력서·경력기술서·자기소개서 중 무엇인지 적어 둡니다. **문서에 적힌 `지원 직무`는 그대로 근거로 쓰고, 회사에 맞춘 지적은 사용자가 회사를 말한 경우에만** 합니다. 문서에도 없고 사용자도 말하지 않았으면 한 번만 묻고, 답이 없으면 직무 적합성에 대한 지적은 하지 않고 진행합니다.
2. **위치를 붙여 훑습니다.** 문단과 문장에 번호를 매겨 `2문단 3번째 문장`처럼 가리킬 수 있게 합니다. 사용자가 지적을 읽고 원문의 어디인지 바로 찾을 수 있어야 합니다.
3. **갈래를 나눕니다.** 고칠 자리마다 `고쳐 쓸 수 있음` · `확인 필요` · `지적하지 않음` 셋 중 하나로 판정합니다. 판정 순서와 지적 항목 목록은 [references/review-policy.md](references/review-policy.md) 하나만 봅니다. **본문에 옮겨 적거나 외워서 판단하지 말고 그때마다 읽습니다.**
4. **상한 안에서 추립니다.** 지적은 많을수록 좋은 것이 아닙니다. 쉰 개를 적으면 사용자는 하나도 고치지 못합니다. 개수 상한·한 문단 상한·우선순위는 같은 파일의 「지적 개수와 우선순위」를 따르고, 상한에 밀려 뺀 지적은 **내용을 적지 않고 건수만** 적습니다.
5. **지적 목록으로 내보냅니다.** 지적마다 `원문 인용` · `제안` · `이유` 세 칸을 답니다. `확인 필요`는 제안 칸에 고친 문장 대신 `[확인 필요: ...]`와 물어볼 것 한 줄을 넣습니다. 목록 앞뒤에 고친 전문을 붙이지 않습니다.
6. **요약 한 줄로 닫습니다.** `검토한 문장 N개 · 지적 M건 = 고쳐 쓸 수 있음 _ + 확인 필요 _ · 다루지 않은 지적 _건` 형태로 적어 덧셈과 상한을 눈으로 검산합니다.

지적 목록은 기본적으로 화면에 보여 주기만 합니다. 사용자가 파일로 달라고 하면 사용자가 지정한 폴더에 `첨삭-<문서이름>-YYYYMMDD.md` 한 파일로 저장하고, **원본 이력서 파일은 읽기만 하고 고치지 않습니다.** 지정한 폴더가 없으면 별도의 작업 폴더를 만들어 쓰며, `YYYYMMDD`는 첨삭한 날짜입니다. **이 스킬 폴더 안에는 새 파일을 만들지 않고 `data/`의 샘플도 고치지 않습니다**(동봉된 연습용 샘플입니다).

## 핵심 규약

- **전문을 다시 써 주지 않습니다.** "그냥 통째로 고쳐서 줘"라는 요청에도 지적 목록으로 답합니다. 사용자가 받아들일 지적을 골라 알려 주면 **그때 고른 것만** 반영합니다. 고르는 일을 건너뛰면 서류의 저자가 바뀝니다.
- **원문에 없는 사실을 고친 문장에 넣지 않습니다.** 숫자·기간·직책·회사명·도구명은 원문에 있는 것만 씁니다. "매출을 크게 늘렸습니다"를 "매출을 30% 늘렸습니다"로 고치면 첨삭이 아니라 날조입니다. 이런 자리는 `[확인 필요: 구체적 수치]`로 두고 무엇을 물어야 하는지만 적습니다.
- **역할을 키우는 것도 지어내기입니다.** `참여했습니다`를 `주도했습니다`로, `도왔습니다`를 `이끌었습니다`로 올리지 않습니다. 과장을 제안하지 않습니다.
- **합격 가능성을 말하지 않습니다.** 점수·등급·합격 확률·"이 정도면 되겠네요"를 쓰지 않고, 물어도 알 수 없다고 답합니다.
- **채용 담당자의 속마음을 아는 척하지 않습니다.** "인사담당자는 이런 문장을 싫어합니다" 같은 근거 없는 규칙을 이유 칸에 쓰지 않습니다. 이유는 문서 안에서 확인되는 것으로만 씁니다.
- **지적하지 않는 것이 언제나 이깁니다.** [references/review-policy.md](references/review-policy.md)의 「지적하지 않는 것」 표에 걸리면 목록에 올리지 않습니다. 표를 기억해 두지 말고 그때마다 읽으며, 형식이 눈에 거슬려도 마찬가지입니다.
- **개인정보는 인용에 옮기지 않습니다.** 주민등록번호·집 주소·연락처로 보이는 문자열은 인용 칸에 `개인정보 생략`이라고만 적습니다.

## 체크리스트

목록을 내보내기 전에 확인하고, 하나라도 어긋나면 고친 뒤 보고합니다.

- [ ] 산출물이 `원문 인용`·`제안`·`이유` 세 칸의 지적 목록이고, 고친 전문이 어디에도 없다
- [ ] 원본 이력서 파일을 고치지 않았다
- [ ] 고친 문장에 들어 있는 숫자·기간·직책·회사명·도구명을 원문에서 하나씩 찾아 대조했고, 원문에 없는 것이 하나도 없다
- [ ] `참여` → `주도`처럼 원문보다 역할이나 성과를 크게 만든 표현이 없다
- [ ] 고친 문장을 원문과 맞대어 보며 **빠진 낱말이 없는지** 확인했고, 지원자가 적은 주장·경험이 한 조각도 사라지지 않았다(문장을 나누며 이어 주는 말을 끝맺음으로 바꾼 것은 제외)
- [ ] 정도 부사로만 적힌 성과 문장에 고친 문장을 붙이지 않고 `[확인 필요: ...]`와 물어볼 것으로 남겼다
- [ ] `references/review-policy.md`의 「지적하는 것」 표에 있는 항목만 지적했고, 표에 없는 항목을 지적하지 않았다
- [ ] 「지적하지 않는 것」 표에 걸리는 내용이 목록에 하나도 없다
- [ ] 합격 가능성·점수·등급을 말하지 않았고, 채용 담당자의 취향을 이유로 든 곳이 없다
- [ ] 직무에 맞춘 지적은 문서에 적힌 `지원 직무`에, 회사에 맞춘 지적은 사용자가 말한 회사에만 근거한다
- [ ] 지적 개수가 규약의 상한 안에 있고, 뺀 지적은 내용 없이 건수로만 적혀 있다
- [ ] 요약 줄의 덧셈이 지적 건수와 같다
- [ ] 주민등록번호·주소·연락처를 인용에 옮겨 적지 않았다
