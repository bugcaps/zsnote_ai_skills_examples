# 콘텐츠 캘린더 기획

**언제 어느 채널에 무엇을 발행할지**를 날짜 단위로 정하고 기록합니다. 기록처가 연결돼 있으면 거기에 쓰고, 없으면 멈추지 않고 CSV로 강등해 저장합니다. 여기서 MCP는 에이전트를 노션·구글 캘린더 같은 외부 서비스에 연결하는 표준 규격을 뜻합니다.

## 작업 순서

1. **조건 확인**: 발행 대상(브랜드·제품), 기간, 채널, 주당 횟수를 확인합니다. **질문은 4개까지만** 합니다. 답이 없는 항목은 기본값(기준 시작일 다음 달 1일 · 기간 4주 · 채널 블로그+인스타그램 · 주 2회)을 쓰고, 무엇을 가정했는지 표 아래에 적습니다.
2. **캘린더 초안**: 항목마다 `발행일 · 요일 · 채널 · 주제 · 형식 · 담당 · 상태`를 **정할 수 있는 만큼 채우고 나머지는 빈 슬롯으로 둡니다.** "화·금"처럼 요일로 남기지 않고 **실제 날짜로 환산**합니다. 브랜드·제품 정보가 없으면 주제는 `(제안)`으로 표시하고 확정하지 않습니다.
3. **기록처 판정**: 지금 쓸 수 있는 도구 목록에서 노션 계열 → 캘린더 계열 순으로 쓰기 도구를 찾고, **판정 결과를 사용자에게 먼저 알립니다.** 판정 순서와 기록처별 필드 매핑은 [references/calendar-targets.md](references/calendar-targets.md)를 따릅니다.
   - 쓰기 도구가 있으면 → 4단계로 갑니다.
   - 없으면 → **4단계를 건너뛰고** `python scripts/make_calendar_csv.py`로 CSV를 저장한 뒤 5단계로 갑니다. 명령 형식과 종료 코드는 위 참조 파일에 있습니다.
4. **쓰기 전 확인**: **생성할 항목 수와 기록 위치**(데이터베이스·캘린더 이름)를 보여주고 진행해도 되는지 묻습니다. 승낙 없이 기록하지 않습니다. 남의 워크스페이스에 레코드가 생기는 일입니다.
5. **보고**: 어느 경로로 기록했는지, 항목이 몇 개 생겼는지, 건너뛴 항목이 있으면 그 이유를 함께 전달합니다.

산출물 **맨 앞줄에 기록처를 표시합니다.** 예: `기록처: 노션 데이터베이스 "콘텐츠 캘린더"` / `기록처: 로컬 CSV(노션·캘린더 MCP 미연결)`
여기서 "산출물"은 사용자에게 보여주는 표·메시지의 첫 줄입니다(CSV 첫 줄은 스펙대로 헤더입니다).

## 핵심 규약

- **추가만 합니다.** 기존 항목의 수정·삭제·이동은 하지 않습니다.
- **같은 날짜·채널에 항목이 이미 있으면 쓰지 않고 건너뜁니다.** 건너뛴 항목은 보고에 남깁니다. 중복 레코드는 되돌리기 어렵습니다.
- **MCP가 없으면 CSV로 갑니다.** 직접 API 호출 코드를 작성하지 않고, 토큰·워크스페이스 ID·데이터베이스 ID를 사용자에게 요구하지 않습니다.
- **한 번에 최대 4주치**까지만 기록합니다. 더 필요하면 4주를 마친 뒤 다시 확인받습니다.
- **카피 본문은 쓰지 않습니다.** 주제와 형식까지만 정하고 본문은 빈 슬롯으로 둡니다.
- 도달·조회·전환 같은 성과 예측 수치를 캘린더에 적지 않습니다. 캘린더는 발행 계획이지 예측표가 아닙니다.

## 체크리스트

- [ ] 질문 4개 이내이고, 가정한 기본값을 표시했다
- [ ] 모든 항목이 요일이 아니라 실제 날짜다
- [ ] 기록처 판정 결과를 사용자에게 알렸다
- [ ] (쓰기 경로) 항목 수와 대상을 보여주고 승낙을 받았다
- [ ] (CSV 경로) 파일을 저장하고 "MCP 미연결" 사유를 함께 보고했다
- [ ] 산출물 첫 줄에 기록처가 표시돼 있다
- [ ] 4주치 이내이고, 카피 본문·성과 예측 수치가 없다
