# 와이어프레임 및 화면 설계서 작성

화면의 시각적 요소와 인터랙션을 분리하여 마크다운 표 형태의 구조화된 화면 설계서를 작성합니다.

## 작업 순서

1. 요구사항을 분석하여 화면의 구역을 크게 3~4개(Header, Content Body, Footer 등)로 나눕니다.
2. `assets/wireframe-template.md`의 구조를 읽어 템플릿의 형식을 파악합니다.
3. 각 구역별로 시각적 요소(UI Components)와 사용자 인터랙션(Actions)을 분리하여 마크다운 표로 명세합니다.
4. 아래 체크리스트로 자가 점검한 뒤 결과를 보고합니다.

## 핵심 규약

- **UI와 액션을 분리합니다.** "버튼을 누르면 이동함"처럼 섞어 쓰지 말고, [UI 요소] 열과 [인터랙션] 열을 명확히 나눕니다.
- **모호한 형용사를 배제합니다.** "예쁜 버튼", "적당한 여백" 대신 "Primary Button", "Text color: #999" 등 구체적 명사와 값을 사용합니다.
- **예외 상태를 포함합니다.** 데이터가 없을 때(Empty State)와 로딩 중일 때(Loading State)의 화면 상태를 반드시 하단에 별도 표기합니다.

## 체크리스트

작성 후 다음을 확인하고, 하나라도 어긋나면 고친 뒤 보고합니다.

- [ ] `assets/wireframe-template.md`의 형식을 준수했는가
- [ ] UI 요소와 인터랙션 열이 명확히 분리되어 있는가
- [ ] 주관적 형용사가 배제되고 구체적 명사로 작성되었는가
- [ ] Empty State와 Loading State 처리가 명시되어 있는가
