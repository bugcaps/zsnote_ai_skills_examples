# 다국어 로컬라이제이션

번역이 좋은지는 사람이 판단하고, 변하면 안 되는 것은 `assets/glossary.json`에 적어 두고 스크립트가 판정합니다.

## 작업 순서

1. **용어집을 먼저 읽습니다.** `assets/glossary.json`에서 대상 로케일, 번역 금지 목록, 용어집 대응어, 자리표시자 표기를 확인합니다. 이 파일에 없는 용어를 임의로 고정 번역어로 정하지 않습니다.
2. **경로를 고릅니다.** 번역 요청이면 3번부터, 이미 있는 번역본 점검 요청이면 4번부터 진행합니다. 점검만 하는 요청이어도 **원문 JSON이 필요합니다.** 없으면 사용자에게 원문 파일을 먼저 요청하고, 받기 전에는 검사하지 않습니다.
3. **번역합니다.** 저장 위치는 사용자가 지정한 폴더이고, 지정이 없으면 별도의 작업 폴더를 만들어 `<이름>.<로케일>.json`으로 씁니다. **이 스킬 폴더의 `data/`에는 새 파일을 만들지 않고, 안에 있는 파일도 고치지 않습니다**(동봉된 연습용 샘플입니다). 원문과 같은 키를 하나도 빠뜨리지 않고 쓰고, 자리표시자(`{plan_count}`, `{{user_name}}`)와 번역 금지 항목은 번역하지 않고 **복사**합니다. 조사나 경칭은 기호 밖에 붙입니다(`{{user_name}}님`).
4. **검사합니다.** 로케일마다 이 명령의 세 자리를 자기 파일 경로와 로케일로 바꿔 실행합니다.

   ```bash
   node scripts/check-l10n.js <원문.json> <번역.json> <로케일>
   # 예: node scripts/check-l10n.js data/source.ko.json data/translation.en.json en
   ```

5. **결과를 읽습니다.** 출력은 `LEVEL 키 [검사명] 메시지` 한 줄씩이고, 마지막 `요약:` 줄에 건수가 있습니다. 종료 코드 1은 ERROR가 있다는 뜻입니다. **번역 경로**에서는 ERROR가 난 문자열만 고쳐 4번을 다시 실행하고, 지적되지 않은 문자열은 건드리지 않습니다. 용어집 ERROR는 지적된 단어만 대응어로 바꾸되, 단어만 바꿔서 문장이 어색해지면 그 문자열 하나를 다시 번역합니다. **점검 경로에서는 번역본을 고치지 않습니다.** 남이 만든 번역본은 요청 없이 수정하지 않고 위반 목록만 보고하며, 고칠지는 사용자가 정합니다.
6. **보고합니다.** 스크립트 출력을 그대로 인용합니다. 로케일이 여러 개면 로케일마다 출력을 따로 인용하고 마지막에 로케일별 ERROR·WARN 건수를 한 줄로 모으며, 한 로케일이라도 ERROR가 남아 있으면 전체를 미완료로 보고합니다. 용어집에 없어서 직접 판단한 용어는 "용어집 추가 후보"로 따로 적습니다.

## 핵심 규약

- **번역을 끝냈다고 보고하지 않습니다.** 검사 스크립트를 실행하고 그 출력을 인용한 뒤에 보고합니다. "용어집을 준수했습니다" 같은 자평 문장은 쓰지 않습니다.
- `glossary.json`과 `check-l10n.js`는 고치지 않습니다. 규칙이 잘못됐다고 판단되면 고치지 말고 보고합니다.
- ERROR는 고칠 대상, WARN은 확인할 대상입니다. WARN을 없애려고 원문이나 용어집을 바꾸지 않습니다.
- **원문·번역 파일은 중첩 없는 `"키": "문자열"` 형태여야 합니다.** 중첩된 파일은 검사되지 않고 통과합니다.
- `요약:` 줄의 "문자열 N개"는 **원문** 개수입니다. 번역문의 키 개수를 따로 세어 원문과 같은지 비교합니다.
- **이 검사는 번역이 맞는지 판정하지 않습니다.** 종료 코드 0은 "표기 규칙 위반이 없다"는 뜻이며 "오역이 없다"는 뜻이 아닙니다. 원어민 검수를 대체하지 않고, 문화적 적합성·관용구·유머·톤은 검사 대상이 아닙니다.
- 용어집 검사에는 오탐과 미탐이 있습니다. 조사·활용·복수형 때문에 대응어가 변형되면 놓치므로, ERROR가 0건이어도 사람이 한 번 읽어야 합니다.
- **약관, 의약·금융 표시, 개인정보 고지 문구는 이 스킬로 번역하지 않습니다.** 담당 부서와 전문 번역을 거칩니다.

## 체크리스트

- [ ] 번역을 시작하기 전에 `assets/glossary.json`을 읽었다
- [ ] 로케일마다 검사 스크립트를 실행했고, 번역 경로에서는 종료 코드가 0이다(점검 경로에서는 위반 목록과 종료 코드를 고치지 않고 그대로 보고했다)
- [ ] 보고서에 인용한 위반 건수가 스크립트 출력의 `요약:` 줄과 일치한다
- [ ] 번역문에 원문의 모든 키가 있다(빠진 키는 WARN으로만 잡힙니다)
- [ ] WARN을 한 건씩 판단하고 그 근거를 보고에 적었다
- [ ] 자리표시자와 번역 금지 항목을 글자 그대로 옮겼다
- [ ] 용어집에 없어서 직접 정한 용어를 "용어집 추가 후보"로 보고했다
- [ ] `glossary.json`과 `check-l10n.js`를 고치지 않았다
