# CI 파이프라인 구축

워크플로우를 처음부터 작성하지 않습니다. `assets/`의 템플릿을 프로젝트에 맞게 고치는 것이 이 스킬의 전부입니다.

## 작업 순서

1. **환경 분석**: 패키지 매니저 파일(`package.json`, 락 파일)을 읽어 런타임 버전(`engines`, `.nvmrc`)과 실제로 존재하는 스크립트(`lint`, `test`, `build`)를 확인합니다.
2. **기존 워크플로우 확인**: `.github/workflows/`에 파일이 있으면 읽습니다. 액션 버전과 러너는 **기존 파일을 따릅니다.**
3. **템플릿 적용**: `assets/node-ci.yml`을 복사해 버전·브랜치·단계를 프로젝트에 맞게 고칩니다. 맞는 템플릿이 없는 언어라면 같은 구조(체크아웃 → 런타임 설정+캐시 → 설치 → 린트 → 테스트)로 작성하고, 템플릿 없이 작성했음을 알립니다.
4. **저장 및 보고**: `.github/workflows/ci.yml`로 저장하고 체크리스트 결과와 템플릿에서 바꾼 부분을 보고합니다.

## 핵심 규약

- **`package.json`에 없는 스크립트를 실행하는 단계를 넣지 않습니다.** `lint`가 없으면 린트 단계를 뺍니다.
- 액션 버전은 템플릿(또는 기존 워크플로우)의 메이저 태그를 그대로 씁니다. 기억에 의존해 버전을 바꾸지 않습니다.
- 의존성 설치는 락 파일 기준 명령(`npm ci`)을 쓰고 캐시를 켭니다.
- 시크릿 값을 파일에 쓰지 않습니다. 필요하면 `${{ secrets.NAME }}`으로 참조하고 등록할 이름을 보고에 적습니다.
- 기본 브랜치 이름은 추측하지 않고 `git symbolic-ref refs/remotes/origin/HEAD` 등으로 확인합니다.

## 체크리스트

- [ ] 모든 `run` 단계의 스크립트가 `package.json`에 실제로 있다
- [ ] 트리거 브랜치가 저장소의 기본 브랜치와 일치한다
- [ ] 런타임 버전이 프로젝트 설정과 일치한다
- [ ] 의존성 캐시가 켜져 있다
- [ ] 시크릿이 평문으로 들어가지 않았다
