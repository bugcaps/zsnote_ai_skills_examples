# 폴더 정리와 되돌리기

파일 정리에서 어려운 것은 분류가 아니라 **되돌리기**입니다. "이렇게 옮길까요?"라고 미리 물어도 소용이 없습니다. 수백 개 목록을 사용자가 제대로 읽을 리 없고, 잘못됐다는 것은 며칠 뒤에 압니다. 그때 필요한 것은 승인 기록이 아니라 **이동 로그**입니다. 그래서 파일을 직접 옮기지 않고 로그를 남기는 스크립트에 맡깁니다.

## 작업 순서

1. **폴더 경로를 받습니다.** 사용자가 "다운로드 폴더"처럼 말하면 실제 경로를 확인받습니다. 하위 폴더는 건드리지 않으므로, 폴더 안의 폴더까지 정리하려면 각각 따로 실행해야 한다고 알립니다.
2. **먼저 미리보기를 돌립니다.** `python scripts/organize_files.py "<폴더>"` — 아무것도 옮기지 않고 무엇이 어디로 갈지만 보여 줍니다. 사진을 날짜로 묶어 달라고 하면 `--by date` 를 붙입니다.
3. **범주 이름과 건수만 옮겨 적습니다.** 파일 목록을 전부 나열해 승인받으려 하지 않습니다. 대신 "옮긴 뒤에도 한 번에 되돌릴 수 있다"는 것과 되돌리는 명령을 미리 알립니다.
4. **실제로 옮깁니다.** 같은 명령에 `--apply` 를 붙입니다. 로그를 쓰지 못하면 스크립트가 종료 코드 2로 멈추고 한 건도 옮기지 않습니다. 이때는 원인을 먼저 해결합니다.
5. **결과를 보고합니다.** `옮김 / 건너뜀 / 실패` 세 숫자와 **이동 로그 파일 경로**, 그리고 되돌리는 명령 한 줄을 반드시 적습니다. 종료 코드가 1이면 실패한 파일이 제자리에 남아 있다는 뜻이므로 사유를 함께 적습니다.
6. **되돌려 달라고 하면 로그로 되돌립니다.** `python scripts/organize_files.py --undo "<이동 로그 경로>"` 로 전부 제자리에 돌려놓습니다. 로그 경로를 모르면 기본 폴더 `~/file-organizer-logs/` 에서 가장 최근 `move-*.csv` 를 찾아 확인받습니다.

이동 로그는 기본값으로 `~/file-organizer-logs/` 에 저장합니다. **정리 대상 폴더 안에 로그를 두지 않습니다**(로그 자신이 정리 대상이 되어 버립니다). 이 스킬 폴더 안에는 새 파일을 만들지 않고, `data/` 의 샘플도 고치지 않습니다(동봉된 연습용 샘플입니다).

## 핵심 규약

- **에이전트가 직접 파일을 옮기지 않습니다.** 옮기는 일은 전부 스크립트에 맡깁니다. 손으로 옮기면 로그가 남지 않아 되돌릴 수 없습니다.
- **무엇도 지우지 않습니다.** 옮기기만 합니다. 중복으로 보이는 파일도 지우지 않고, 비게 된 폴더도 지우지 않습니다. "정리하면서 필요 없는 건 지워 줘"라는 요청에는 지우지 않는다고 답하고 옮기기만 합니다.
- **덮어쓰지 않습니다.** 대상 폴더에 같은 이름이 이미 있으면 그 파일은 옮기지 않고 제자리에 둡니다. 스크립트가 `건너뜀` 으로 세어 주므로, 이 건수를 보고서에 적고 두 파일 중 무엇을 남길지는 사용자가 정하게 합니다.
- **분류 규칙은 스크립트의 `CATEGORY_RULES` 한 곳에서만 정합니다.** 보고서에서 범주를 새로 만들거나 이름을 바꾸지 않습니다. 분류를 바꾸려면 그 목록을 고친 뒤 다시 실행합니다.
- **`--by date` 의 날짜는 파일 이름에 적힌 날짜가 먼저이고, 없으면 파일의 수정 시각입니다.** 수정 시각은 **찍은 날이 아니라 마지막으로 고치거나 내려받은 날**입니다. 촬영일(EXIF)은 읽지 않습니다. 사진을 촬영일 기준으로 묶어야 한다면 이 스킬로는 보장할 수 없다고 먼저 말합니다. 날짜를 정할 수 없는 파일은 `_날짜모름/` 으로 갑니다.
- **확장자가 없는 파일은 `_확장자없음/`, 목록에 없는 확장자는 `_기타/` 로 갑니다.** 확장자만 보고 내용을 짐작해 범주를 바꾸지 않습니다.
- **이름이 점으로 시작하는 숨김 파일과 하위 폴더는 건드리지 않습니다.** 설정 파일이 섞여 있어도 옮기지 않습니다.
- **미리보기를 승인 절차로 쓰지 않습니다.** 목록을 길게 붙여 놓고 "확인하셨죠?"라고 묻지 않습니다. 안전장치는 사용자의 확인이 아니라 로그입니다.

## 체크리스트

보고하기 전에 확인하고, 하나라도 어긋나면 고친 뒤 보고합니다.

- [ ] 파일을 직접 옮기지 않고 스크립트로만 옮겼다
- [ ] `--apply` 전에 미리보기를 한 번 돌렸다
- [ ] 이동 로그 파일의 **실제 경로**를 보고서에 적었고, 그 파일이 존재하는지 확인했다
- [ ] 되돌리는 명령(`--undo <로그 경로>`)을 사용자가 그대로 복사할 수 있게 한 줄로 적었다
- [ ] 로그가 정리 대상 폴더 밖에 있다
- [ ] `옮김 / 건너뜀 / 실패` 세 숫자를 모두 적었고, 종료 코드 1이면 실패한 파일의 사유를 적었다
- [ ] 종료 코드 2로 시작하지 못했다면 세 숫자는 **해당 없음**으로 두고(출력되지 않습니다), "한 건도 옮기지 않았습니다"와 그 사유만 적었다
- [ ] 이름 충돌로 건너뛴 파일이 있으면 건수와 대처를 적었다
- [ ] 지운 파일이 없다
- [ ] 범주 이름이 스크립트 출력과 같고, 새로 만든 범주가 없다
- [ ] `--by date` 를 썼다면 날짜 기준이 수정 시각이라는 점을 알렸다
