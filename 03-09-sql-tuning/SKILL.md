# SQL 쿼리 최적화 및 튜닝

패턴 검출은 스크립트가, 해석과 재작성은 에이전트가 맡습니다. 기본 대상은 MySQL이며 다른 엔진이면 먼저 확인합니다.

## 작업 순서

1. **정적 검사**: 쿼리를 임시 파일로 저장한 뒤 `python scripts/analyze-sql.py <파일>`을 실행합니다. 쿼리를 명령행 인자로 넘기지 않습니다(따옴표와 `%`가 깨집니다).
2. **정보 확인**: 테이블 구조(`SHOW CREATE TABLE`)와 `EXPLAIN` 결과가 없으면 사용자에게 요청합니다. 받지 못하면 **가정을 명시**하고 진행합니다.
3. **쿼리 재작성**: `FOUND`로 보고된 항목부터 고칩니다. 스크립트는 정규식 기반이므로 결과는 후보로 다루고, 오탐이면 그 이유를 적습니다.
4. **EXPLAIN 해석**: 결과가 있으면 `type: ALL`, `Using filesort`, `Using temporary`, `rows` 추정치를 근거로 병목을 설명합니다.
5. **인덱스 제안**: 컬럼 순서와 그 이유(등치 조건 → 범위 조건 → 정렬)를 함께 적습니다.

## 핵심 규약

- **개선 쿼리는 원본과 같은 결과를 반환해야 합니다.** 결과가 달라지는 변경(`LIKE '%김%'` → `LIKE '김%'`, `LEFT JOIN` → `INNER JOIN` 등)은 적용하지 않고 "의미가 바뀌는 대안"으로 따로 제시합니다.
- 스키마에 없는 테이블·컬럼·인덱스를 지어내지 않습니다.
- 쿼리를 DB에 직접 실행하지 않습니다. `EXPLAIN`도 사용자에게 실행을 요청합니다.
- 인덱스는 쓰기 비용이 있으므로 쿼리 하나에 최대 1개만 제안합니다.

## 체크리스트

- [ ] 스크립트를 실행했고 출력을 보고에 포함했다
- [ ] 개선 쿼리가 원본과 같은 결과를 내는 이유를 설명했다
- [ ] 의미가 바뀌는 변경은 별도 대안으로 분리했다
- [ ] 제안한 인덱스의 컬럼 순서와 이유를 밝혔다
- [ ] 스키마를 모르고 가정한 부분을 명시했다
