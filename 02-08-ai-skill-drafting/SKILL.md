# 커밋 메시지 작성

diff에서 알 수 있는 것만 쓰고, 메시지를 보여 주는 데서 멈춥니다. 커밋은 사람이 합니다.

## 작업 순서

1. `git diff --cached`로 스테이징된 변경을 읽습니다. 비어 있으면 그렇다고 알리고 멈춥니다.
2. `git branch --show-current`로 브랜치 이름을, `git log -5 --oneline`으로 최근 커밋 첫 줄의 언어와 scope 표기를 확인합니다.
3. 아래 규약대로 메시지를 써서 코드 블록 하나로 보여 줍니다.
4. 체크리스트로 점검하고, 어긋나면 고친 뒤 보여 줍니다.

## 핵심 규약

- **첫 줄**은 `type(scope): 요약`, 50자 이내입니다. type은 `feat`, `fix`, `refactor`, `docs`, `test`, `chore` 중에서 고릅니다. 요약의 언어와 scope 표기는 최근 커밋을 따릅니다.
- **본문**은 한국어로, 무엇을 왜 바꿨는지만 두세 줄로 씁니다. 상수 값, 함수 이름, 반복 구조처럼 어떻게 구현했는지는 diff에 있으므로 쓰지 않습니다.
- **왜**는 diff·브랜치 이름·사용자의 말에 근거가 있을 때만 씁니다. 없으면 이유를 지어내지 않고 `[TODO: 변경 이유 확인]`으로 남깁니다.
- **이슈 번호**는 브랜치 이름에 숫자가 있을 때만 맨 끝 줄에 `Refs #<번호>`로 붙입니다. 없으면 붙이지 않고 지어내지 않습니다.
- `git commit`을 실행하지 않고, "이 메시지로 커밋할까요?"라고 묻지도 않습니다.

## 형식

```text
<type>(<scope>): <요약, 50자 이내>

<무엇을 바꿨는지 한 줄>
<왜 바꿨는지 한두 줄. 근거가 없으면 [TODO: 변경 이유 확인]>

Refs #<브랜치 이름에 있는 번호. 없으면 이 줄을 지움>
```

## 체크리스트

- [ ] 첫 줄이 50자 이내이고 type이 목록 안에 있다
- [ ] 본문에 구현 방법(값·함수 이름)이 없다
- [ ] 본문의 "왜"를 diff·브랜치 이름·사용자의 말에서 찾을 수 있다(없으면 `[TODO: 변경 이유 확인]`)
- [ ] `Refs` 번호를 브랜치 이름에서 찾을 수 있다(없으면 줄이 없다)
- [ ] 커밋을 실행하지 않았다
