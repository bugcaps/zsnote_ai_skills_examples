# 커밋 메시지 작성

## 절차

1. `git diff --cached`로 스테이징된 변경을 확인한다. 스테이징된 변경이 없으면 그렇다고 말하고 멈춘다.
2. `git branch --show-current`로 브랜치 이름을 확인한다.
3. 아래 형식으로 메시지를 작성해서 코드 블록으로 보여 준다.

## 형식

```
type(scope): 요약

무엇을 왜 바꿨는지 한국어로 두세 줄.

Refs #번호
```

- **첫 줄**: Conventional Commits 형식 `type(scope): 요약`, 50자 이내
  - type: `feat`, `fix`, `refactor`, `docs`, `test`, `chore` 등
  - 호출부가 영향을 받는 동작 변경(반환값, 예외, 시그니처 변경 등)이면 `type(scope)!:`처럼 `!`를 붙인다
- **본문**: 한국어로, **무엇을 왜** 바꿨는지만 두세 줄로 쓴다
  - 어떻게 구현했는지(상수 값, 함수 호출, 루프 구조 등)는 diff에 있으므로 쓰지 않는다
  - `!`를 붙였다면 무엇이 바뀌는지(예: "None 대신 TimeoutError가 발생한다")를 본문에 적는다
- **이슈 번호**: 브랜치 이름에 번호가 있을 때만(예: `fix/123-login-timeout`) 맨 끝에 `Refs #123`을 붙인다. 없으면 붙이지 않고 번호를 지어내지 않는다

## 하지 말 것

- `git commit`을 실행하지 않는다. 커밋은 사용자가 직접 한다
- "이 메시지로 커밋할까요?"라고 묻지 않는다

## 예시

```
fix(login)!: enforce client timeout with retries

로그인 요청이 느리면 끝까지 기다렸다가 응답을 버리고 None을 반환하는 문제가 있었다.
일시적인 지연으로 로그인이 실패하지 않도록 재시도하게 했다.
타임아웃이 나면 이제 None 대신 TimeoutError가 발생한다.

Refs #123
```
