# tradeoff-verification-hitl 사용 예시

## 요청

"API 응답 속도를 개선할 수 있나?"

## 에이전트의 동작

```
1️⃣ Bash: 두 가지 최적화 방안 구현 & 벤치마크
   - 옵션 A: 인덱싱만 추가 (간단, 약간의 성능 향상)
   - 옵션 B: 캐싱 + 인덱싱 (복잡, 큰 성능 향상)

2️⃣ Artifact: 성능 비교표
   
   지표        | 현재    | 옵션 A | 옵션 B
   -----------|--------|-------|-------
   응답시간    | 500ms  | 350ms | 100ms
   캐시 관리   | 없음   | 없음  | 필요
   복잡도     | 낮음   | 낮음  | 높음
   개발 시간   | -      | 1일   | 3일

3️⃣ AskUserQuestion: "어디로 할까요?"
   "A) 빠른 개발 (1일) vs
    B) 최고 성능 (3일)
    
    [옵션 A] [옵션 B]"
```

## 산출물

```
✅ 두 가지 옵션 성능 측정 완료
✅ 정량화된 데이터 제시
✅ 사용자 선택: 옵션 B (성능 중요)
✅ 선택된 옵션으로 구현
```

## 핵심

- 객관적 데이터만
- 트레이드오프 명확히
